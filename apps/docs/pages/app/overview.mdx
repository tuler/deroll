# Core

The `@deroll/core` module provides the composition an application needs to share one rollup loop between several handlers.

[`Rollup.run`](/app/application) in the binding takes exactly **one** advance handler and **one** inspect handler. A real application usually has more than one concern per request kind — a wallet that claims portal deposits, then the application's own logic — so `@deroll/core` provides the functions that fold many handlers into one.

```ts twoslash
/// <reference types="node" />
import { Rollup } from "@cartesi/rollup";
import { createWallet } from "@deroll/wallet";
import { createRouter } from "@deroll/router";

const rollup = new Rollup();
const wallet = createWallet();
const router = createRouter();
const application = () => true;
// ---cut---
import { chain } from "@deroll/core";

rollup.run({
    advance: chain(wallet.handler, application),
    inspect: router.handler,
});
```

That is the whole runtime surface:

- [chain](/app/chain) — present the input to each handler until one accepts it.
- [broadcast](/app/broadcast) — present the input to every handler regardless.

## Types

`@deroll/core` also owns the handler types, and re-exports the rollup protocol's vocabulary from `@cartesi/rollup` so that the two can never drift:

| Type | Description |
| --- | --- |
| `AdvanceRequestHandler` | Handles a state-changing input; returns a boolean. |
| `InspectRequestHandler` | Handles a read-only query; returns nothing. |
| `RollupContext` | The slice of the `Rollup` a handler is handed — the emit methods, `progress` and `gio`. |
| `AdvanceRequest`, `InspectRequest` | The request shapes, re-exported. |
| `Voucher`, `DelegateCallVoucher` | The output shapes, re-exported. |
| `BytesLike`, `AddressLike`, `U256Like`, `Hex` | Byte and numeric aliases, re-exported. |

`RollupContext` is deliberately narrower than `Rollup`: it omits `finish`, `run`, `close` and the merkle methods, which belong to whoever owns the loop. It is also a structural type rather than the class, so a handler's tests can pass a plain object instead of mocking the native binding.

## Everything else

The rest of deroll is libraries you plug in as handlers, and the outputs they help you build:

- [wallet](/app/wallet) — an asset ledger that parses portal deposits and builds withdrawal vouchers.
- [router](/app/router/overview) — URL-pattern dispatch for inspect queries.
