# Emitting Outputs

While handling a request your application can emit four kinds of outputs. They differ in what they can do and in what can be *proven* about them on-chain:

| Output | Provable | Purpose |
| --- | --- | --- |
| [Call voucher](/codec/encode-call-voucher) | yes | Execute a transaction on-chain (transfer ether, call a contract) |
| [Asset transfers](/codec/encode-asset-transfers) | yes | Typed ERC-20/721/1155 transfers out of the application |
| [Notice](/codec/encode-notice) | yes | Attest a fact about the application state |
| [Report](/rollup/reference/emit-report) | no | Logs, diagnostics, inspect responses |
| [Exception](/rollup/reference/emit-exception) | no | Signal that the request could not be processed |

Provable outputs are built in two steps: an `encode*` helper produces the EVM-ABI encoded bytes, and [`emitOutput`](/rollup/reference/emit-output) adds them to the application's **outputs merkle tree**, returning the output's index. Reports and exceptions are emitted directly as plain bytes.

## Vouchers: act on-chain

A voucher is a one-shot transaction the application authorizes: when the epoch containing it settles, anyone can execute it through the application contract. Use it to transfer assets out, call DeFi protocols, or trigger any on-chain effect:

```ts twoslash
import { Rollup } from '@deroll/rollup';
import { encodeCallVoucher } from '@deroll/codec';
const rollup = new Rollup();
// ---cut---
// transfer 1 ETH from the application contract to a user
const index = rollup.emitOutput(
    encodeCallVoucher({
        destination: '0xf39Fd6e51aad88F6F4ce6aB8827279cffFb92266',
        value: 1_000_000_000_000_000_000n, // wei
        payload: '0x', // no calldata — plain value transfer
    }),
);
```

To call a contract, put the EVM calldata in `payload`. For plain token withdrawals, prefer the typed asset-transfer outputs below.

## Asset transfers: withdraw tokens

The new rollups contracts understand first-class asset-transfer outputs, so an application transfers ERC-20/721/1155 tokens out without hand-crafting calldata:

```ts twoslash
import { Rollup } from '@deroll/rollup';
import { encodeErc20Transfer } from '@deroll/codec';
const rollup = new Rollup();
// ---cut---
rollup.emitOutput(
    encodeErc20Transfer({
        recipient: '0xf39Fd6e51aad88F6F4ce6aB8827279cffFb92266',
        token: '0x6B175474E89094C44Da98b954EedeAC495271d0F',
        value: 10n ** 18n,
    }),
);
```

See the [asset transfer encoders](/codec/encode-asset-transfers) for the ERC-721 and ERC-1155 (single and batch) variants.

## Notices: attest facts

A notice carries no on-chain action — it is a verifiable statement that "the application, having processed inputs up to this point, says X". Typical uses: settlement results, state snapshots, anything an off-chain consumer wants to trust without re-executing the machine:

```ts twoslash
import { Rollup } from '@deroll/rollup';
import { encodeNotice } from '@deroll/codec';
import { Hex } from 'ox';
const rollup = new Rollup();
// ---cut---
const result = { winner: '0xf39F…2266', prize: '1000' };
rollup.emitOutput(encodeNotice({ payload: Hex.fromString(JSON.stringify(result)) }));
```

## Reports: observe and debug

Reports are for everything that doesn't need a proof: log lines, error messages, and answers to [inspect queries](/rollup/guide/handling-requests#inspect-requests). They cost nothing on-chain and cannot be verified:

```ts twoslash
import { Rollup } from '@deroll/rollup';
const rollup = new Rollup();
// ---cut---
rollup.emitReport(Buffer.from('debug: cache warmed up'));
```

## Exceptions: give up loudly

An exception tells the outside world the request could not be processed at all — a structural failure rather than a business-rule rejection. Prefer returning `false` from a handler (or throwing, which [run](/rollup/reference/run) turns into a report + rejection); reach for [`emitException`](/rollup/reference/emit-exception) only when the application cannot continue in a meaningful way.

## Output indices and proofs

[`emitOutput`](/rollup/reference/emit-output) returns the output's **index** — its position among all provable outputs ever produced by the application. Persist or report it if an off-chain component needs to locate the output later to fetch its proof and execute/validate it:

```ts twoslash
import { Rollup } from '@deroll/rollup';
import { encodeNotice } from '@deroll/codec';
import { Hex } from 'ox';
const rollup = new Rollup();
// ---cut---
const index = rollup.emitOutput(encodeNotice({ payload: Hex.fromString('state-root:abc123') }));
//     ^?
```

## Byte and number conventions

`emitOutput`, `emitReport` and `emitException` all accept `BytesLike` — converted automatically from three shapes:

```ts twoslash
import { Rollup } from '@deroll/rollup';
const rollup = new Rollup();
// ---cut---
rollup.emitReport('0xdeadbeef'); // 0x-prefixed hex string
rollup.emitReport(Buffer.from('hello')); // Buffer
rollup.emitReport(new Uint8Array([1, 2, 3])); // Uint8Array
```

The `encode*` helpers in [`@deroll/codec`](/codec) take ox-native types — addresses and bytes as 0x-hex strings, numbers as `bigint` — and return the encoded output as a 0x-hex string that `emitOutput` accepts directly. Values from [viem](https://viem.sh) — `Hex` from `encodeFunctionData`, `Address`, `bigint` from `parseEther` — pass in without casts; invalid values raise ox errors before anything reaches the device.

## When libcmt fails

[`emitOutput`](/rollup/reference/emit-output), [`emitReport`](/rollup/reference/emit-report) and [`emitException`](/rollup/reference/emit-exception) can throw a `RollupError` carrying the libcmt error code if the underlying call fails — for example emitting an output larger than the machine's output buffer. The negative errno is available on `error.errno` and the failed call name on `error.syscall`.
